   → Дізнатись ID Марини (написати боту — він відмовить і покаже ID, або @userinfobot) і додати
   через кому в `TELEGRAM_ADMIN_IDS` у `.env` на ноуті магазину.

2. **Задача `HoroshopOrders_TelegramNotify` УВІМКНЕНА на dev-машині (ця, D:\FISH).**
   Кожна машина веде свій `data/notified_orders.json` → коли dev-ноут увімкнений, сповіщення
   про одне замовлення приходять ДВІЧІ. StockSync/Orders тут вимкнені правильно, notify — забули.
   → `Disable-ScheduledTask -TaskName HoroshopOrders_TelegramNotify` на dev-машині.

3. **Альбом фото ламає заливку.** Кілька фото одним повідомленням = кілька викликів
   `handle_photo`; підпис є лише в одного; `state` перезаписується → заливається ЛИШЕ останнє
   фото, решта мовчки губиться. Треба буфер по `media_group_id`.

### 🟡 Важливе

4. **Кнопка «🛒 Замовлення» має побічні ефекти.** Вона запускає `notify_new_orders.py --days 7`,
   який ШЛЕ сповіщення й позначає замовлення надісланими, а в чат вертає сирий stdout у `<pre>`.
   Треба окрема read-only функція «показати замовлення» (список карток без запису в журнал).

5. **Фото документом (без стиснення) бот не приймає** — оброблюється лише `F.photo`.
   Telegram стискає фото до ~1280px; для Rozetka потрібно ≥1000×1000, тобто запас мінімальний.
   Додати обробник `F.document` (mime image/*) + автоперевірку/ресайз розміру.

6. **Черга AI-модерації нежиттєздатна за обсягом:** 3589 `ai_draft` + 2122 `draft`.
   По одній картці «✅/❌» — це тижні тапів. Потрібне пакетне затвердження
   (по сім'ї/категорії) або авто-approve з вибірковою перевіркою.

7. **Падіння polling → 15 хв мовчання** (`asyncio.sleep(900)` у retry-циклі).
   Зменшити до 30–60 с з експоненційним backoff.

8. **`notify_new_orders.py` хардкодить `ROOT = D:\FISH\fish-sync`** (рядок 29) — єдиний з
   бот-файлів, що не перейшов на `Path(__file__)`. На іншому шляху задача тихо зламається.
