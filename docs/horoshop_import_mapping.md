## Маппінг колонок — JS-скрипт (виконати в консолі сторінки)

Після завантаження файлу відкривається "Попередній перегляд імпорту".  
Колонки маппляться через Vuex store, який знаходиться всередині iframe  
`http://shop647643.horoshop.ua/adminLegacy/data.php?handler=17`.

> **Результат фінального запуску:** mapped=89, skipped=160, total=249 — кнопка "Імпортувати" активна, помилок дублікатів немає.

### Крок 1 — Ініціалізувати `window._store` (виконати 1 раз після відкриття сторінки)

```javascript
(function(){
  const iframe = Array.from(document.querySelectorAll('iframe')).find(f => f.src && f.src.includes('adminLegacy'));
  const iDoc = iframe.contentDocument;
  const el = Array.from(iDoc.querySelectorAll('*')).find(e => e.__vue__ && e.__vue__.$store);
  if (!el) return 'NO STORE';
  window._store = el.__vue__.$store;
  return 'store OK: ' + window._store.state.DataGrid.columns.length + ' cols';
})()
```

Якщо повернуло `store OK: 249 cols` — можна запускати крок 2.

### Крок 2 — Виконати повний скрипт маппінгу

```javascript
(function() {
  const store  = window._store;
  const avail  = store.state.DataGrid.availableGroups;
  const header = store.state.DataGrid.rows[0];
  const cols   = JSON.parse(JSON.stringify(store.state.DataGrid.columns));

  const norm = s => (s||'').toLowerCase()
    .replace(/\s*\(ua\)\s*$/i,'').replace(/\s*\(ru\)\s*$/i,'').trim();

  const byNorm = {};
  avail.forEach(a => { const n = norm(a.label); if (!byNorm[n]) byNorm[n] = a.id; });

  // 1. Auto-map by label
  cols.forEach(col => {

  // 2. Manual overrides (null = не імпортувати)
  const M = [

    [147,77],[148,82],[149,104],[150,136],[151,89],[153,100],[154,103],
    [156,130],[157,82],[166,123],[168,121],[169,121],[170,121],[171,121],
    [172,94],[173,121],[174,123],[175,121],[176,123],[178,89],[179,108],
    [180,123],[181,138],[182,123],[184,121],[189,145],[190,123],[191,134],
    [193,104],[195,93],[202,143],[205,139],[209,99],[212,132],[213,77],
    [215,140],[217,144],[219,140],[221,80],[222,79],[224,86],[226,105],
    [229,94],[230,113],[231,82],[232,105],[236,79],[238,93],[240,79],
    [241,79],[244,144],[245,94],[248,132],
  ];
  M.forEach(([f,a]) => { const c = cols.find(x => x.field === f); if (c) c.selected = a; });

  // 3. Deduplicate — кожен avail ID лише один раз
  const availLabel = {};
  avail.forEach(a => { availLabel[a.id] = norm(a.label); });
  const sim = (a, b) => {
    if (a === b) return 999;
    let s = 0;
    a.split(/\s+/).forEach(w => { if (w.length > 2 && b.includes(w)) s += w.length; });
    return s;
  };
  const FORCE_KEEP = { 10: 16, 30: 14 };
  const groups = {};
  cols.forEach(col => {
    const id = col.selected;
    if (id !== null && id !== undefined) {
      if (!groups[id]) groups[id] = [];
      groups[id].push(col);
    }
  });
  Object.entries(groups).forEach(([availId, group]) => {
    if (group.length <= 1) return;
    const aId = parseInt(availId);
    let keepField;
    if (FORCE_KEEP[aId] !== undefined) { keepField = FORCE_KEEP[aId]; }
    else {
      const aLabel = availLabel[aId] || '';
      let best = group[0], bestScore = -1;
      group.forEach(col => {
        const s = sim(aLabel, norm(header[col.field]));
        if (s > bestScore) { bestScore = s; best = col; }
      });
      keepField = best.field;
    }
    group.forEach(col => {
      if (col.field !== keepField) {
        const c = cols.find(x => x.field === col.field);
        if (c) c.selected = null;
      }
    });
  });

  store.commit('DataGrid/setColumns', cols);
  const mapped  = cols.filter(c => c.selected !== null && c.selected !== undefined).length;
  const skipped = cols.filter(c => c.selected === null).length;
  return `OK: mapped=${mapped} skipped=${skipped} total=${cols.length}`;
})()
```

### Пояснення скрипту

| Крок | Що робить |
|------|-----------|
| **1. Auto-map** | Для кожної колонки XML знаходить Horoshop-поле з ідентичною назвою (після нормалізації: lower-case, strip `(UA)`/`(RU)`) |
| **2. Manual overrides** | 101 ручне перевизначення для полів де авто-маппінг дав неправильний результат або треба `null` |
| **3. Deduplicate** | Якщо один avail_id призначений кільком колонкам — залишає найкращий збіг за схожістю назви; FORCE_KEEP: avail 10 → field 16 (stock_quantity), avail 30 → field 14 (vendor) |

## ⚠️ Проблема: ліміт 2000 товарів при імпорті

### Симптом
При імпорті 7823 товарів Horoshop прийняв тільки ~2000. Деякі категорії повністю порожні.

### Причина
Horoshop імпортує товари **по порядку в XML-файлі** і зупиняється після 2000 рядків
(ліміт плану або батч-ліміт).

Перший рядок у XML — це **<categories>**, потім товари йдуть у тому порядку, в якому
`render_horoshop.py` їх обробляє. Малі категорії (гачки, повідки, лески) опиняються
**першими** (рядки 1–2000), а великі категорії взагалі не потрапляють до імпорту:

| catId | Назва | Кількість | Перший рядок у XML |
|-------|-------|-----------|-------------------|
| 2901  | Блешні | 755 | після 2000 |
| 1020  | Силікон (Приманки) | 714 | після 2000 |
| 2902  | Воблери | 538 | після 2000 |
| 2001  | (велика категорія) | 362 | після 2000 |
| 1901  | (велика категорія) | 334 | після 2000 |

**55 з 74 категорій** мають 0 товарів у перших 2000 рядках XML.

### Варіанти вирішення

#### Варіант А — Перевірити план Horoshop (рекомендовано спочатку)
Якщо це **ліміт плану** → треба оновити тариф.  
Зайти: Horoshop → Налаштування → Тариф/Підписка.  
Якщо там написано "до 2000 товарів" — потрібен апгрейд.

#### Варіант Б — Переупорядкувати товари в XML (якщо це батч-ліміт)

Відредагувати `render_horoshop.py` — виставити пріоритет категорій.  
Файл: `D:\FISH\fish-sync\src\render_horoshop.py`

Поточний порядок визначається ітерацією по `TIP_TO_CAT_ID`.  
Рішення: відсортувати категорії за кількістю товарів (спочатку найбільші).

```python
# В render_horoshop.py — зібрати всі товари і відсортувати перед виводом
# Приблизна логіка:
all_products = []
for tip, cat_id in TIP_TO_CAT_ID.items():
    products = get_products_for_tip(tip)
    all_products.extend(products)

# Сортувати: спочатку топові категорії
PRIORITY_CATS = [2901, 1020, 2902, 2001, 1901]  # Блешні, Силікон, Воблери ...
all_products.sort(key=lambda p: (
    0 if p['catId'] in PRIORITY_CATS else 1,
    -count_by_cat.get(p['catId'], 0)
))
```

#### Варіант В — Імпорт частинами
Якщо ліміт — 2000 на один імпорт:
1. Відфільтрувати XML: окремий файл для кожної великої категорії
2. Проводити імпорт кілька разів з різними XML-файлами
3. Для кожного — запускати маппінг-скрипт з кроку 2 вище

## Структура XML-колонок (field index → XML тег / param name)

Перший рядок таблиці — це хедер (назви XML тегів), не реальний товар. Індекси стабільні для `horoshop.xml`:

```
field 0  → offer id (= артикул, не імпортуємо — дубль)
field 1  → Код вендора (ігноруємо)
field 2  → <article>
field 3  → <categoryId>
field 4  → <name> (RU-мітка — є дубль у field 15)
field 5  → <price>
field 6  → <old_price> (нема в XML — ігнор)
field 7  → <currencyId>
field 8  → Наличие від available attr (ігнор — є field 16)
field 9  → <picture>
field 10 → Описание(RU) (ігнор)
field 11 → Доставка (ігнор)
field 12 → Страна производства (ігнор)
field 13 → Отображать
field 14 → <vendor> (Бренд)
field 15 → <name_ua>
field 16 → <stock_quantity>
field 17 → <article> дубль (ігнор)
field 18 → <description_ua>
field 19+→ <param name="..."> значення характеристик
```

## Важливі нотатки

1. **parentId в категоріях**: НЕ виставляти `parentId` в XML — Horoshop шукає категорію за
   шляхом `/Батько/Дитина`, і якщо слаги не налаштовані — не знаходить. Без `parentId`
   шукає тільки по назві → завжди знаходить. Код у `render_horoshop.py`: `parent_attr = ""`

2. **Маппінг через Vuex** (не через DOM): кнопки `gp.onSelect()` не працюють напряму —
   потрібно `store.commit('DataGrid/setColumns', cols)`.

3. **Iframe**: весь UI імпорту — всередині iframe `adminLegacy/data.php?handler=17`,
   тому JS треба виконувати через `window._store` (ініціалізувати через крок 1 вище).

4. **Перший рядок даних** — це хедер (назви XML тегів), не реальний товар.

5. **Колонки з params** мають непостійні індекси якщо XML згенерований з іншим
   набором характеристик — тому скрипт завжди варто запустити з `console.log` перевіркою.

6. **MySQL row size limit**: Після ~42 VARCHAR(255) колонок у `h_product_characteristics`
   досягається ліміт InnoDB. Характеристики 43+ ОБОВ'ЯЗКОВО створювати з `type=select`
   (значення в окремій lookup-таблиці, обходить ліміт).

7. **avail_id зсув**: TEST_CHAR_DELETE (6611, avail_id=72) і TEST_CAPTURE2 (6612, avail_id=95)
   вставились між оригінальними param IDs. Тому старий маппінг (72=Тип вудилища) ЗАСТАРІВ.
   Актуально: 73=Тип вудилища, 74=Тип насадки, ..., 94=Розмір.

8. **Створення params**: endpoint `POST /adminLegacy/params/ajax.php` з `action=saveParam`.
   При maintenance Horoshop повертає 503 "Сайт тимчасово недоступний".

9. **Ліміт 2000 товарів**: Horoshop зупиняє імпорт після 2000 рядків. Щоб усі 7823 товарів
   потрапили — або оновити план, або переупорядкувати XML (великі категорії першими).
   Дивись секцію "Проблема: ліміт 2000 товарів" вище.
