# Як додати нові товари (конвеєр, перевірено 2026-06-10)

> Весь шлях: УкрСклад7 → канонічний каталог → сайт. Жодних ручних дій в адмінці Horoshop.

## Коротко

1. Марина додає товар в **УкрСклад7** (NAME, KOD, TIP/група, ціна, залишок).
2. **Залишки і ціни** на сайт підтягнуться автоматично (щогодинна задача
   `UkrSkladToHoroshop_StockSync`), але НОВИЙ товар на сайті від цього не з'явиться.
3. Щоб новий товар **з'явився на сайті** (з назвою, описом, категорією, брендом, ціною):

```powershell
cd D:\FISH\fish-sync
# 1) перечитати УкрСклад у products.json (робить і щогодинний синк)
python src\sync_stock_playwright.py --dry-run        # оновлює data\products.json

# 2) перевірити, як новий товар ляже в каталог (сім'я/категорія/опис)
python src\render_horoshop.py                        # перегенерує public\horoshop.xml
#    знайти артикул у public\horoshop.xml і переглянути назву/категорію/опис

# 3) створити товар(и) на сайті — режим create (9 колонок:
#    артикул, назва, назва модифікації, Розділ, Бренд, Ціна, Валюта, Наявність, Опис)
python src\sync_content_playwright.py --articles НОВИЙ_АРТИКУЛ --mode create

#    або всі нові одразу (оновить існуючі + створить відсутні):
python src\sync_content_playwright.py --mode create
```

4. Результат у консолі: `Обновлено: N; Добавлено: M` — "Добавлено" = створені нові.
5. Фото: класти у `F:\FISH_IMAGES` і заливати наявними фото-скриптами
   (див. docs/HOROSHOP_PHOTO_AGENT_RUNBOOK.md), формат `{артикул}@gallery_common.jpg`.

## Як товар отримує категорію/характеристики/опис АВТОМАТИЧНО

- **Сім'я** товару визначається `detect_family()` у `src/catalog_rules.py`:
  спершу за групою УкрСкладу (SOURCE_CATEGORY_RULES), потім за ключовими словами назви.
  45 сімей. Нова сім'я = додати запис у SOURCE_CATEGORY_RULES + FAMILY_LABELS.
- **Категорія сайту** (`parent`, формат "Вудилища / Махові") — теж із catalog_rules.
- **Характеристики**: DEFAULT_COMMON_PARAMS по сім'ї + regex-екстракція з назви
  (довжина/тест/діаметр/вага...) + `enrich_obvious_param_pairs()` у horoshop_catalog.py.
- **Опис**: `src/description_templates/<family>.py` — пули фраз (вибір детермінований
  по hash артикула), реальні параметри вплітаються в текст. БЕЗ AI-кліше.
  Якщо Марина схвалить AI-опис у Telegram-боті (status='approved' в meta_store) —
  він матиме пріоритет над шаблоном.

## Оновлення вже існуючих товарів

```powershell
# тільки назви+описи (швидко, безпечно):
python src\sync_content_playwright.py --mode mod
# тільки ціни/залишки — робить планувальник щогодини, вручну:
python src\sync_stock_playwright.py
```

## Важливі факти (здобуті 2026-06-10, не загубити!)

| Факт | Деталь |
|---|---|
| Опис передається через `--desc-mode escape` (default) | Horoshop розекранує і зберігає справжній HTML (`<p>`, `<ul>`) |
| `raw` режим НЕ працює | парсер бере innerText — теги губляться |
| H1 товару на вітрині = **назва модифікації** | тому завжди шлемо `mod_title-_-3` = назві товару (режими mod/create) |
| Створення нових = режим `create` | обов'язкові колонки: Розділ (формат "Батько / Дитина"), інакше товар не створиться |
| Результат імпорту | "Обновлено: N; Добавлено: M" на pricelist.php |
| SEO категорій | `python src\fill_category_seo.py` — seo_text + title + description для всіх 125 категорій |
| SEO-текст категорії видно тільки на чистому URL | на URL з `?query` Horoshop його не рендерить (захист від дублікатів) |

## SEO товарів (додано 2026-06-10)

Індивідуальні HTML title + META description для ВСІХ товарів (перебивають глобальний шаблон):

```powershell
python src\sync_content_playwright.py --mode seo          # всі товари, ~90с
python src\sync_content_playwright.py --mode seo --articles НОВИЙ_АРТИКУЛ
```

Формули в `build_product_seo()` (sync_content_playwright.py):
title = "{Назва} — купити в Україні | Все для рибалки", description з ціною і вигодами.
Запускати після додавання нових товарів (після --mode create).

## Нативні фіди маркетплейсів (увімкнено 2026-06-10)

В адмінці Маркетинг → Маркетплейси увімкнені **Rozetka Feed** і **Facebook Feed**
(legacy handler=429, ids 3 і 4). Файли фідів Horoshop генерує сам за розкладом —
посилання на фід дивитись у налаштуваннях відповідного фіда в адмінці
(розділ рендериться як iframe legacy: /adminLegacy/data.php?handler=429).
Ці фіди містять фото з CDN — для кабінетів Rozetka/Facebook використовувати САМЕ їх,
а не локальні public/rozetka.xml / facebook.xml (ті без фото).

## ⚠ Артикули з провідними нулями/крапками (000276, 00.10) — КРИТИЧНО (2026-06-11)

pricelist.php **нормалізує артикули на СЕРВЕРІ** (000276→276) і мовчки відкидає такі рядки —
жоден масовий імпорт їх не бачить. Через це 629 товарів були взагалі відсутні на сайті.

**Рішення:** `python src\create_missing_products_by_form.py` — створення/правка через
legacy-форму товару (addnew, handler=381), вона артикули НЕ псує. Правила:
- з blank-форми **викидати ВСІ порожні поля** (порожні FK-селекти типу installments_payment,
  supplier_id валять INSERT помилкою Integrity constraint violation);
- категорія = параметр `parent={page_id}` + `parent_common[parent]`; шлях каталогу →
  page_id через data/category_tree_site.json (alias "всі"→батько, fuzzy по дітях);
- наявність: modifications[0][presence] = 1 (В наявності) / 2 (Немає);
- progress-файл data/created_missing_progress.json — скрипт відновлюваний.

Нові категорії, створені 2026-06-11: **Одяг та взуття** (id 1322, /odiah-ta-vzuttia/, у Туризмі)
та **Подарункові сертифікати** (id 1323, /podarunkovi-sertyfikaty/). Слаги для НОВИХ категорій
треба генерувати віджетом `updateUriAutomatically` (інакше створяться без URL).

## Чого конвеєр НЕ робить (межі)

- **Характеристики на сайт** масово не імпортуються: legacy-імпортер не показує
  поля характеристик у dropdown (блокер з 2026-06-07). Характеристики на сайті —
  з травневого YML-імпорту. Для нових товарів характеристики потраплять у фіди
  (rozetka/facebook/horoshop.xml), але НЕ на сторінку сайту, поки не буде нової
  хвилі YML-імпорту через адмінку або модуля API.
- **Facebook-фід без фото** для більшості товарів (фото живуть на CDN Horoshop,
  а не локально). Рішення: увімкнути нативний модуль "Експорт товарів" у Horoshop
  (Меню → Експорт) — він генерує фіди з фото сам. Поки фід не підключений до FB — не критично.
