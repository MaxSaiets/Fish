Звідси відчуття «нічого нормального немає».

### Чому статистика була беззмістовною (виправлено 29.07)
- Показувала `ai_draft / draft / published` — стани AI-конвеєра, а не бізнесу.
- `✅ Опубліковано` **завжди 0**: статус `published` у коді не ставиться ніде.
- `📦 Всього 5711` — це parent-моделі, а товарів **8759**. Цифри не сходились ні з чим.

**Зроблено:** `src/bot_dashboard.py` — дашборд по реальних метриках (замовлення,
каталог, фото, виручка, свіжість синку) + кнопки «🏆 Топ продажів» і
«⚠️ Закінчилось з топу». Черга AI лишилась окремим блоком.

## 2. ПЛАН: ЩО БОТ МАЄ ВМІТИ

Пріоритет за принципом «скільки грошей це приносить/рятує».

### 🔴 РІВЕНЬ 1 — гроші (робити першим)

**1.1. Замовлення прямо в боті**
Зараз сповіщення шле окремий скрипт `notify_new_orders.py` (кожні 10 хв, задача
Планувальника). Це працює, але живе окремо від бота.
- [ ] Кнопка «🛒 Нові замовлення» — список необроблених
- [ ] Картка замовлення: клієнт, телефон, товари, сума, спосіб доставки
- [ ] Кнопка «✅ Оброблено» → списати зі складу УкрСкладу (`sync_orders.py` вже вміє)
- [ ] Кнопка «📞 Подзвонити» → `tel:` лінк
- [ ] Перенести сповіщення всередину бота (один процес замість двох)

**1.2. Фото товарів прямо з телефона** ⭐ найцінніше
96% каталогу — заглушки, це блокує Rozetka і Google Shopping.
- [ ] Марина шле фото в бота з підписом-артикулом → бот заливає на товар
- [ ] Бот сам питає «до якого товару?» якщо підпису немає (пошук за назвою)
- [ ] Кнопка «📸 Що фоткати далі» — топ-10 товарів без фото за продажами
- [ ] Лічильник прогресу: «залито 12 з 200 пріоритетних»
Механізм заливки вже працює (`upload_horoshop_images.py`: check → upload → assign).

**1.3. Контроль залишків топ-товарів**
- [x] «⚠️ Закінчилось з топу» — зроблено
- [ ] Автосповіщення, коли топ-товар падає в нуль (а не тільки за запитом)
- [ ] «Замовити у постачальника» — нотатка/нагадування

## 5. ОБМЕЖЕННЯ, ПРО ЯКІ ТРЕБА ПАМʼЯТАТИ

- Бот працює, **поки ноутбук увімкнений** (VPS немає). Вимкнули — сповіщення
  прийдуть при наступному вмиканні.
- Horoshop API на цьому тарифі недоступний (409) — усе через Playwright/pricelist,
  тобто повільніше і крихкіше.
- Товари, створені новим редактором, стара форма віддає 503 — редагуються лише
  через pricelist-імпорт по артикулу.
- Шаблон 381 не чіпати (SQL FK-баг ламає товари).
