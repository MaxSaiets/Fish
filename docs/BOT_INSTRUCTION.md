# ЧАСТИНА 1. ДЛЯ МАРИНИ (щоденна робота)

Бот — це магазин у телефоні. Пишете йому в Telegram, він показує товари,
приймає фото і повідомляє про замовлення.

## Початок

Напишіть боту `/start` — з'явиться меню з кнопками:

```
[🛒 Замовлення]   [🔎 Знайти товар]
[📸 Що фоткати]   [📊 Статистика]
[⚙️ Ще]
```

## 🛒 Замовлення

**Нове замовлення приходить САМО** — бот перевіряє сайт кожні 10 хвилин і
надсилає повідомлення: номер, ім'я, телефон, товари, сума, посилання в адмінку.

Кнопка «🛒 Замовлення» показує всі замовлення за 7 днів (просто подивитись —
нічого не змінює).

**Списувати товар вручну НЕ ТРЕБА** — проданий товар зникає з залишків
УкрСкладу автоматично, раз на годину, і на нього створюється видаткова накладна.

## 📸 Що фоткати — найкорисніша функція

У магазину 7 043 товари без справжнього фото — це головна причина, чому сайт
погано продає, і чому товари не пускають на Розетку.

1. Натисніть «📸 Що фоткати» — бот покаже 10 товарів, які варто зняти першими.
2. Сфотографуйте товар телефоном.
3. Надішліть фото боту, а **в підпис напишіть артикул** (наприклад `1497`).
4. Бот заллє фото на сайт і покаже картку товару з посиланням.

Дрібниці, які варто знати:
- Можна надіслати **кілька фото одразу** (альбомом) — перше замінить заглушку,
  решта додадуться в галерею.
- Забули підпис — бот сам запитає артикул, просто надішліть його наступним повідомленням.
- Знімайте на світлому однорідному фоні, товар цілком у кадрі. Бот сам збільшить
  фото до потрібного розміру.
- Якщо надсилаєте «як файл» — якість буде ще краща.

## 🔎 Знайти товар

Натисніть кнопку або просто напишіть боту:
- **назву** («вудка», «котушка feima») — покаже список із цінами й залишками;
- **артикул** (`1497`) — покаже картку: ціна, залишок, бренд, характеристики,
  посилання на товар на сайті.

## 📊 Статистика

Стан магазину: скільки замовлень оброблено, скільки товарів у наявності,
скільки ще без фото, коли востаннє оновлювались дані з УкрСкладу.

## Що приходить автоматично

| Коли | Що |
|---|---|
| кожні 10 хв (при новому замовленні) | 🎣 картка замовлення |
| коли ходовий товар падає в нуль | 🔻 «варто замовити» |
| якщо синхронізація стоїть >24 год | ⚠️ попередження |
| щопонеділка | 🗓 тижневий звіт |

## Чого бот НЕ робить

- Не працює, коли **ноутбук магазину вимкнений** (свого сервера немає).
  Увімкнули — усе пропущене прийде.
- Не показує виручку й обсяги продажів (навмисно прибрано 04.08.2026).
- Кнопки в «⚙️ Ще» — технічні, для Max. Краще не чіпати.

# ЧАСТИНА 2. ДЛЯ MAX (супровід)

## Головна команда

```bash
python src\diagnose.py
```

Повністю **read-only** перевірка всього ланцюга: нічого не пише в УкрСклад,
не вантажить на сайт, не шле повідомлень. Показує:

- стан 4 задач Планувальника + коли востаннє відпрацювали і з яким кодом;
- чи знайдена база УкрСкладу, скільки товарів, **скільки списань із сайту вже зроблено**;
- останні прогони (залишки / замовлення), чи не були вони випадково dry-run;
- чи живий токен бота і скільки отримувачів сповіщень;
- **порівняння сайту з УкрСкладом** — наявність і ціни на вибірці товарів.
  Це прямий доказ, доїжджають залишки чи ні.

Те саме доступне з телефона: «⚙️ Ще» → «🧪 Діагностика».

> Звіт стосується ЛИШЕ тієї машини, де запущений. У ноута магазину і ноута
> розробки різні бази й різні журнали.

## Меню «⚙️ Ще»

| Кнопка | Що робить |
|---|---|
| 🩺 Перевірка системи | швидка перевірка: сайт, база, дані, диск |
| 🧪 Діагностика | повна перевірка ланцюга (вище) |
| ⚠️ Треба замовити / Малий залишок | що закінчилось / залишок ≤3 |
| 🆕 Останні додані · 🌐 На сайті | нові товари · живий лічильник із сайту |
| ✏️ Змінити ціну / залишок | правка одного товару: `артикул значення` |
| 🤖 AI-описи | по одному або «⚡ Затвердити всі якісні» |
| 🔄 Синхронізація | залишки / замовлення / повний цикл — вручну |
| 👥 Доступ | видати/забрати доступ до бота прямо з телефона |
| 📥 Оновити бота · 🛑 Стоп процеси | оновлення коду + рестарт · вбити фонові процеси |

## Запуск і задачі

```bash
python src\telegram_bot.py            # бот вручну
python src\telegram_bot.py --simulate # логіка без Telegram
python src\notify_new_orders.py --test # тест сповіщень
python src\notify_new_orders.py --list --days 7  # подивитись замовлення, нічого не змінюючи
python src\sync_stock_playwright.py --dry-run    # залишки без запису на сайт
python src\sync_orders.py --dry-run              # замовлення без запису в УкрСклад
```

Задачі Планувальника (створює `docs\setup_scheduled_tasks.ps1`):

| Задача | Період | Призначення |
|---|---|---|
| `UkrSkladToHoroshop_StockSync` | 2 год | ціни й наявність УкрСклад → сайт |
| `HoroshopOrders_ToUkrSklad` | 1 год | замовлення → списання + накладна |
| `HoroshopOrders_TelegramNotify` | 10 хв | сповіщення + автоалерти |
| `FishSyncBot` | при вході в систему | сам бот (без таймліміту) |

**Усі чотири мають бути увімкнені ТІЛЬКИ на ноуті магазину.** На інших машинах —
вимкнути, інакше подвійні сповіщення й ризик подвійного списання.

## Додати користувача (напр. Марину) — з телефона, без ноутбука

1. Людина пише боту будь-що (або `/whoami`) — він відповість і **покаже її ID**.
2. У боті: «⚙️ Ще» → «👥 Доступ» → «➕ Додати людину» → надіслати `<id> Марина`.
3. Усе. Діє одразу, перезапуск не потрібен.

Видані так люди бачать **лише бізнес-кнопки** — технічне меню «⚙️ Ще» їм
недоступне. Список зберігається в `data/bot_admins.json` (не в git).
Прибрати доступ: там же «➖ Прибрати видану з телефона».

Власники системи лишаються в `.env` (`TELEGRAM_ADMIN_IDS`) — їх із телефона не
прибрати, це захист від випадкового самовиключення. Якщо технічне меню треба
замкнути тільки на себе явно: `TELEGRAM_TECH_IDS=1311004971` у `.env`.

## Обмеження, про які треба пам'ятати

- **Кількість товару на сайт не передається** — канал імпорту Horoshop має лише
  колонку «Наявність» (є/немає), колонки «кількість» у ньому немає взагалі.
  Тому в адмінці сайту в усіх товарів кількість = 0, і це нормально.
  Реальні залишки бот бере напряму з УкрСкладу.
- API Horoshop на цьому тарифі вимкнений (409) — усе через Playwright, повільно.
- Товари з нового редактора стара форма не редагує (503) — лише через прайс-імпорт.
- Шаблон 381 не чіпати.
- Бот живе, поки ввімкнений ноутбук магазину.

## Якщо щось не працює

| Симптом | Перевірка |
|---|---|
| бот мовчить | `python src\diagnose.py` → задача `FishSyncBot`, токен |
| не приходять замовлення | там же: задача `...TelegramNotify`, «отримувачів сповіщень» |
| залишки на сайті старі | там же: блок «Наявність на сайті vs УкрСклад» |
| товар не списався | там же: «Списань із сайту» + `logs\orders_*.log` (не dry-run?) |
| код не оновлюється | див. «Оновлення коду» нижче |

## Оновлення коду

Звичайний шлях — кнопка **«📥 Оновити бота»** в «⚙️ Ще». Вона більше не робить
голий `git pull`, а працює через `src/self_update.py`: зберігає робочі журнали
(`notified_orders.json`, `processed_orders.json`, `.offset`…), відкочує їх до стану git,
тягне код і повертає журнали на місце. Якщо ж локально правили САМ КОД — оновлення
чесно зупиниться і назве файл, нічого не затираючи.

Якщо оновленню заважають локальні правки коду, бот покаже їх список і кнопку
**«📦 Зберегти правки і все одно оновити»**: правки копіюються в
`backup_local_<дата>/` (файли + `changes.diff`), і лише тоді код оновлюється.
Журнали замовлень при цьому зберігаються окремо — щоб `reset` не відкотив список
списаних замовлень і те саме замовлення не пішло в УкрСклад удруге.

**Одноразово на ноуті магазину.** Поки там стара версія бота, цієї кнопки ще
немає, тому один раз потрібна команда (перевірено на симуляції 04.08 — код
оновився, журнал `["4","7"]` уцілів, правки збереглись):

Відкрити PowerShell і вставити **чотирма рядками** (не одним через `&&` —
у стандартній Windows PowerShell 5.1 `&&` це синтаксична помилка):

```powershell
cd D:\FISH\fish-sync
git fetch origin
git checkout origin/main -- src/self_update.py
python src\self_update.py --force
```

Третій рядок дістає ОДИН новий файл без злиття, четвертий — оновлює з бекапом.
Далі все робиться кнопкою, ноутбук більше не потрібен.
